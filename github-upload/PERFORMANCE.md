# Performance And Recording Notes

本项目的性能目标不是单纯让游戏画面流畅，而是让录屏文件也保持稳定、清晰、不卡顿。录屏质量是核心目标。

## Priorities

1. 保持录屏画质、分辨率和主要特效表现。
2. 通过缓存和预渲染减少重复计算，而不是直接砍掉效果。
3. 大招、拖尾、发光、录屏同时出现时，优先优化绘制路径。
4. 新增角色时先考虑“录出来是否看得清楚”。

## Recording Pipeline

录屏使用独立录制 canvas，包含：

- 游戏场地画面
- 开局 VS 页面
- 下方角色面板
- 结算胜利页面
- 游戏内音效

已经做过的录屏优化：

- 使用手动提交视频帧，避免只录到第一帧。
- 录屏帧率使用稳定节奏提交。
- 录屏下方角色面板使用缓存层，HP/技能/文案变化时才重绘。
- 开局页静态内容使用缓存层，闪电仍动态绘制。
- 结算页静态内容使用缓存层。
- 2v1 模式仍复用同一录制 canvas，下方三名角色面板并排绘制，开赛页左侧双卡缓存，不影响默认 1v1 的两面板缓存路径。

## High Risk Paths

以下路径新增或调整时，需要格外注意录屏表现：

- `drawRecordingFrame`: 录屏总合成路径。
- `mode=2v1` 角色对战：同场最多 3 个角色控制器，目标选择必须按 `teamId` 过滤；录制面板和开赛页走三人布局，但默认 1v1 不应进入该分支。
- `drawFengxiDomainLines`: 风息（领域）2v1 专用领域技能每 6 秒生成 3 条较短的横穿场地细金属线，使用短生命周期 canvas 线段和共享命中集合，不创建额外大图素材或持续拖尾对象。
- `drawDanjinEyes` / `drawDanjinIntroEffect` / `drawDanjinBreakEffect`: 2v1 灵遥断金阵开局生成 7 个固定阵眼；魔法阵和破阵主体复用外部透明 PNG 并提前缓存金色贴图，阵眼也预渲染为小 canvas sprite，避免开局瞬间每帧创建多个渐变或复杂路径。
- `drawUltimateEffects`: 浩克飞镰、鹿野追毫、风息豪夺等大招效果。
- `drawTetheredWire`: 鹿野御金/追毫的柔性丝线和枪头。
- `drawTwinBlades`: 清泉/灵遥双刀残影。
- `drawLuyeTreasureShield`: 鹿野琼圆盾裂纹和碎裂效果。
- `drawFoldingFans` / 西木子戏梦九尾狐投影：飞扇旋转和外部九尾狐 PNG 投影需要控制 glow 半径、素材尺寸和持续时间。
- `drawNezhaFireAura` / `drawQiankunRings`: 哪吒火焰包裹使用外部透明 WebP 火焰环叠加旋转，爆燃期短暂增加尺寸和层数；乾坤圈使用 glow 与轨道绘制，需控制叠加层数和 shadowBlur。
- 虚淮冰河时代：全场冰蓝蒙层、外部冰边框 PNG 和裂纹线持续 3 秒，需保持素材绘制层数有限，避免录屏时大面积透明叠加过重。
- `drawAgenProjectiles` / `drawElementalStatusEffects`: 阿根冰锥和焚焰火使用外部 PNG 小图叠加局部 glow；焚烧状态复用单张外部火球 PNG 做贴身火焰层，火焰层数和火星数量固定，避免每帧创建高密度全屏特效。
- `drawQidaoRocks`: 七刀聚石使用固定 12 个边缘小石头汇聚成 1 个大石头，不生成持续拖尾对象；自爆复用 1 张外部透明爆炸 PNG 加冲击波，持续约 1.1 秒，避免持续全屏效果。
- `drawInfiniteBoomerang` / `drawBlackHoles`: 无限金系召唤复用 1 张抠底且金属化后的外部四刃回旋镖 PNG，低 glow 绘制；领域吞噬叠加 1 张外部黑洞 JPG，并用圆形裁切和 multiply 混合降低白底影响，避免新增多层粒子。
- `drawXuanliProjectiles` / `drawXuanliUltimates`: 玄离冰火每 5 秒只生成 2 条投射物，拖尾间隔采样且固定上限为 12；普通冰火拖尾使用轻量线段绘制，避免每个拖尾点创建 radialGradient；两重天只生成 1 个大招对象，追踪拖尾固定上限为 16，汇聚与追踪阶段复用 canvas 渐变和短拖尾，避免额外素材解码和高频粒子堆积。
- `drawLuoxiaoheiMetalPlates` / `drawLuoxiaoheiTeleports` / `drawLuoxiaoheiClones`: 罗小黑御金、传送和黑咻分身全部使用轻量 canvas 路径与小范围渐变绘制；分身固定 4 个小球，均匀环绕旋转 3 秒后发射，不生成额外拖尾对象；黑洞传送不复用大尺寸外部黑洞素材，避免和其他角色大招同时出现时增加额外解码压力。
- 2v1 风息（领域）视觉：`drawUltimateEffects` 中的 `fengxiDomainIntro` 只在开赛时生成 1 个 2.7 秒白光扩张效果；`fengxiDomainDefeat` 只在风息（领域）阵营最终失败前生成 1 个 5 秒全屏树木/藤蔓覆盖效果，复用既有外部透明树木和藤蔓 PNG，树木与藤蔓实例数量固定，不生成持续粒子对象。
- 足球独立 demo：`soccer.js` 复用主游戏式场地 HUD、开赛页和录制入口；录制使用 1120x700 独立合成 canvas，把足球场、比分 HUD、开赛 VS 页面和结束页绘入同一视频流，避免 DOM 覆盖层漏录；角色球体速度沿用角色对战的 260 档并使用低频巡航目标减少往复抖动，足球使用低摩擦惯性运动、所有碰撞/边界处理后的最低速度约束，以及位移过低时的随机重启防卡住机制，射门拖尾长度固定上限为 14；守门员为每侧 1 个固定门区移动球体，不额外生成粒子。
- 高频音效播放：子弹、碰撞、连续命中、大招爆发。

## Optimization Guidelines

- 静态或低频变化 UI 先画入离屏 canvas，再贴到主画布。
- 大尺寸素材提前缩放缓存，避免每帧重复缩放。
- 避免每帧使用昂贵的 `ctx.filter`；需要调色时优先预渲染缓存。
- 控制 `shadowBlur` 的数量和半径，尤其是多角色同场和录屏时。
- 控制拖尾对象数量和生命周期，避免每帧创建大量对象。
- 大招尽量做局部强冲击效果；必须全屏时，减少持续时间内的重复渐变计算。
- 多条同类投射物同时出现时，使用轻量模式降低 glow，不改变伤害和命中逻辑。

## Verification Checklist

修改录屏、UI 或重型技能后，至少确认：

- 页面能加载到新版本号。
- `node --check game.js` 通过。
- 开局页面可见，开始按钮正常。
- 录制按钮可开始/停止。
- 录制文件非 0 字节。
- 录制视频画面连续，不停在第一帧。
- 角色面板、开局页、结算页能被录入。
- 游戏内音效被录入，麦克风不参与采集。

## Known Tradeoffs

- 当前保存格式为 WebM。MP4/MOV 转换不在浏览器内实时进行，以免引入额外性能风险。
- 全屏大招视觉冲击强，但录屏中最容易造成帧时间波动。后续优先采用缓存层或局部高亮方案。
- 外部素材可提升真实感，但大图需要压缩或预缩放，避免启动和录屏时解码压力过大。
